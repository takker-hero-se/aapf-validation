# Ethical Use Statement

## Summary

This dataset contains synthetic Active Directory and Windows system databases captured from isolated laboratory environments. All synthetic data was generated by published automated tools (`BadBlood`, `PSWindowsUpdate`, `Playwright`, `Atomic Red Team`) operating against fresh OS installs in cloud-isolated infrastructure with no network connectivity to production systems. The dataset contains **no real personally identifiable information, no real user accounts, no real credentials, and no captured data from any production environment**.

The dataset is released for the **validation and regression testing of open-source forensic ESE parsers**.

## What is in the samples

The dataset contains four classes of Extensible Storage Engine database files:

| Category | File | Page size | Source | Synthetic content |
|---|---|---|---|---|
| Identity | `ntds.dit` + `SYSTEM` | 8 KiB / 32 KiB | BadBlood populated AD DC | Synthetic users, groups, computers, OUs, randomized ACL misconfigurations |
| Health | `DataStore.edb` | 16 KiB | PSWindowsUpdate iterations | Windows Update scan / install history entries |
| Activity | `WebCacheV01.dat` | 32 KiB | Playwright automated browsing | Edge / IE web cache entries from a fixed URL list |
| Resource | `SRUDB.dat` | 4 KiB | Atomic Red Team execution | SRUM-recorded process / network / energy entries from low-risk Discovery tests |

The Identity samples in particular contain extractable NT hashes for the synthetic accounts BadBlood creates. These hashes correspond to nonexistent users in a nonexistent domain and have no use against any production system.

## Generation provenance

- **Infrastructure**: Microsoft Azure compute (Standard_B2s VMs), isolated to a research subscription with no peering to production tenants.
- **BadBlood**: `davidprowe/BadBlood` (GPL-3.0), commit pinned in `docs/BADBLOOD_PROVENANCE.md`. Default population profile.
- **PSWindowsUpdate**: PowerShell Gallery module, version pinned in `docs/BADBLOOD_PROVENANCE.md`.
- **Playwright**: Microsoft Edge Chromium channel, automated via Playwright Python.
- **Atomic Red Team**: Selected Discovery tactic tests (T1082, T1016, T1033, T1057, T1018, T1087) only. No Persistence, Defense Evasion, or Credential Access tests were executed.

See `docs/BADBLOOD_PROVENANCE.md` for the exact commit hashes, versions, and execution parameters.

## Intended use

- **Validation and regression testing of open-source ESE forensic parsers** — particularly `libesedb`, Impacket's `ese.py`, Fox-IT's `dissect.esedb`, and downstream tools that depend on these parsers.
- **Reproduction of the empirical claims** in the companion paper (FSI:DI 2026 — see `docs/PAPER.md`).
- **Conformance testing** for new parser implementations against a corpus that covers 4 KiB / 8 KiB / 16 KiB / 32 KiB pages and Clean / Crashed / Locked snapshot states.
- **Education and training** in ESE-format forensic analysis.

## Not intended use

- Use against any production Active Directory deployment.
- Use as a source of "training data" for credential-cracking tooling targeting real environments.
- Aggregation with other datasets in a manner that could de-anonymize anyone (no anonymization is needed because no real persons are referenced; the warning is included for completeness).

## Why we believe public release is appropriate

The forensic-research community has, for over two decades, relied on publicly available synthetic corpora to support reproducible research:

- [Garfinkel, "Bringing Science to Digital Forensics with Standardized Forensic Corpora"](https://doi.org/10.1016/j.diin.2009.06.016) (DFRWS 2009 Best Paper) explicitly argues that publishing synthetic forensic corpora is a precondition for the field's maturation as a science.
- [NIST CFReDS](https://www.nist.gov/itl/ssd/software-quality-group/computer-forensics-tool-testing-program-cftt) publishes test images for forensic tool validation including credentials-containing samples.
- The DFRWS forensic challenges have historically distributed lab-generated AD and registry artifacts under similar terms.
- Fox-IT's `dissect.esedb` test suite ships synthetic `.dat` and `.edb` test fixtures for parser regression.

Our release fits this established pattern. The dataset is not novel in the sense of presenting new attack capability; it is a synthetic, reproducible test corpus.

## Responsible disclosure timeline

The underlying parser failures documented by this dataset were responsibly disclosed to maintainers before public release:

- **2026-02-10** — `libesedb` issue [#78](https://github.com/libyal/libesedb/issues/78) opened (the 32 KiB case had previously been reported but unfixed).
- **2026-06-14** — universal-patch finding (16 KiB and 4 KiB cases) shared with maintainers and recorded in this dataset.
- **2026 (Q3)** — paper accepted at FSI:DI; full disclosure simultaneous with dataset publication.

By the time of public release, downstream patched parsers (Poneglyph, an example of which is included here) are available to mitigate any forensic-tool-validation gap introduced by the disclosure.
